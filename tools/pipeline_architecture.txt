# CREATION PIPELINE — TWO-PASS EXECUTION ORDER (SUNO ONLY)

**Scope:** Every Path A / B / C generation. Defines **sequence only** — detailed rules live in the modules cited below.

**Platform:** **Suno only** (v4.5 / v5.0 / v5.5). Udio support is temporarily disabled — do not optimize density, style-field shape, or metatags for Udio.

**Unified orchestrator:** **SUNO V4 MASTER PRODUCTION ARCHITECTURE** (Platinum v4.0 five-layer chain).

**Silent:** Never print stage names, DNA JSON, blueprint labels, score tables, or “I revised because…” in the user-visible reply.

**Product:** Deliver only **BLOCK 1 — PASTE INTO SUNO: STYLE** + **BLOCK 2 — PASTE INTO SUNO: LYRICS** (+ follow-ups after `[End]`) per SECTION 0.

**Architecture:** Prefer **two LLM passes** when `PROMPT_PIPELINE=two_pass` (or `architect`). If a single call is used, run **Pass 1 cognition silently**, then emit **Pass 2 product only**. Do **not** self-score or run an internal auto-revision monologue — external runtime owns format QA and retries.

---

## PASS 1 — THE ARCHITECT (planning)

Silent planning. When the runtime asks for a structured blueprint, output **JSON only**. Otherwise keep all of this internal.

| Step | Stage | Apply rules from |
|-----:|-------|------------------|
| 1 | **USER INPUT** | User message (genre, mood, theme, references, BPM, analyser, path flags) |
| 2 | **Artist DNA analysis** | ARTIST DNA TRANSLATION ENGINE — traits only; **no** artist/song/album names in output |
| 3 | **Genre engine** | Genre vault, SECTION 1A–1F, genre templates, GENRE REFERENCE APPENDIX (translation lexicon only) |
| 4 | **Songwriting mode engine** | Human Songwriter Engine v3.0 — §3 Mode A/B/C |
| 5 | **Master blueprint engine** | Music Creation Intelligence — `<master_blueprint>` §6; align `commercial_score` with `songwriting_mode` |
| 6 | **Audience engine** | HIT SONG PSYCHOLOGY ENGINE — AUDIENCE ENGINE |
| 7 | **Emotional target engine** | Music Creation `transformation_arc` + Human Songwriter §2 |
| 8 | **Listener transformation engine** | Music Creation §6 + Hit Song — LISTENER TRANSFORMATION ENGINE |
| 9 | **Rhythmic quantization & Hook psychology** | Music Creation §2–§4 · Hit Song §3 (`<psychology_audit>`) |
| 10 | **Conflict resolution** | Reconcile Genre ↔ Artist DNA ↔ Mode before Pass 2. If DNA phrasing fights the genre (e.g. soft narrative pop DNA on death metal), rewrite DNA traits and blueprint fields until cohesive. Loop steps 2–5 as needed. |

**Pass 1 output (when runtime requests JSON):** genre, BPM/key intent, mode A/B/C, emotion/transformation arc, hook concept, section roadmap, syllable/density targets — **no** Block 1 prose, **no** lyric lines.

## PASS 2 — THE LYRICIST & PROMPTER (execution)

Takes the Pass 1 blueprint (JSON from runtime, or silent internal plan). Focus on creative emission + Suno formatting.

| Step | Stage | Apply rules from |
|-----:|-------|------------------|
| 11 | **Lyrics generation** | Human Songwriter v3.0 (`<lyric_audit>`) + SECTION 2 / genre Block 2 templates + MELODY-SYNC + BLOCK 2 protocol |
| 12 | **Arrangement & metatag engine** | **SUNO METATAG SYNTAX** whitelist + **ARRANGEMENT STAGING FORMAT** — map sections to allowed `[brackets]` only; no invented tags |
| 13 | **Humanization & AI-cliché detection** | HUMAN AUTHENTICITY → §12 NIGERIA CULTURAL REALISM (when applicable) → GENRE-SPECIFIC HUMANIZATION + Elite Human Lyricist + BLOCK 2 bans |
| 14 | **Block 1 & Block 2 emission** | SECTION 0 Block 1 prose + SUNO SIGNAL + path checklists + mastering blueprints; Block 2 through `[End]` |

**Do not run in-prompt:** quality score tables, “FINAL RELEASE TEST” numeric self-grades, or multi-turn self-revision essays. External QA replaces former steps 14–15 self-scoring.

**Recency bias:** Absolute hard constraints (Block 1 ≤150 words / ≤1000 chars, Block 2 brackets through `[End]`, no internal thoughts in output) are restated at the **end** of the user message by the runtime when needed.

## RUNTIME POST-PROCESSING (after generation, before user sees output)

### OpenRouter pipeline (default)

| Step | Model | Pass | Role |
|-----:|-------|------|------|
| 0 | **Qwen 3.7** | Generate | Genre · structure · arrangement · hooks · theme |
| 1 | **Qwen 3.7** | Theme consistency | Block 2 — one emotional world, no drift |
| 2 | **Mistral Large** | Humanization | Block 2 — natural phrasing, anti-AI, authenticity |
| 3 | **Qwen 3.7** | Suno compression (Stage 5) | Full output — Block 1/2 caps, paste-ready |

**Not in this chain:** optional **hybrid draft+polish** (`PROMPT_PIPELINE=hybrid`) — separate pre-pass, off by default. Pass 2 step 13 humanization is **in-prompt** during generate, not a duplicate API call.

**LaoZhang:** Terra English / GPT-6 Astra multilingual draft → Claude (`claude-sonnet-4-5`) lyrics polish → theme + **mandatory** humanization (Claude EN · Astra multilingual/Pidgin) → Luna compression.

| LaoZhang step | Model | Handles |
|---------------|-------|---------|
| Prompt draft | Terra (EN) · Astra (multilingual) | Multilingual understanding (African languages, Nigerian Pidgin), full Suno prompt generation |
| Lyrics polish | Claude Sonnet 4.5 | Lyrics, hooks, storytelling, vocal personality, artistic expression |
| Theme pass | Claude Sonnet 4.5 | Block 2 editorial consistency |
| Humanization | Claude (English) · GPT-6 Astra (multilingual / Pidgin / African) — mandatory | Same `humanization_pass.txt` as OpenRouter — natural phrasing, anti-AI, dialect rules |
| Compression | GPT-5.6 Luna | Mechanical Suno Block 1/2 caps |

**Token hygiene:** continuation prior output is head+tail truncated (`CONTINUATION_PRIOR_MAX_CHARS`, default 6000). Post-process passes use compact `G:|F:|V:` context headers.

Opt out: `OPENROUTER_POST_PROCESS=false` · `THEME_CONSISTENCY_PASS=false` · `HUMANIZATION_PASS=false` · `SUNO_COMPRESSION_PASS=false`.
